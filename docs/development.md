# 开发与验证

保持 TypeScript 严格检查、Vue Composition API 和 Less；功能按共享模型、主进程服务、preload、组件分层。不要另建 MCP 状态、素材格式或生成队列。接口变化同时更新契约和检查入口。构建产物、个人素材和运行记录不进入 Git；不自动提交。

`npm run check` 包括类型、ESLint、Stylelint、依赖边界与格式检查。`npm test` 为纯领域/静态契约检查：锁定对象、引用完整性、裁切解除和局部更新字段保持。它们不能证明供应商真实可用。

真实验收使用当前本机 Chiyo 和 NovelPrompt 开发实例及实际配置；开始前核对 root/dataDirectory/mode。创建名称带 `[验收]` 的工程/页面，保留现有项目和原图。外部 Agent 必须亲自读取上下文、查看实际图片并提出前台方案，再可见采纳执行。不要用 mock 图片服务或隔离 profile 替代。

针对编辑器，验证鼠标移动/缩放、笔画/格框、文字提交与 Ctrl+S、撤销/重做、锁定、素材版本采用、保存打开及像素/DPI 导出。输入过程中外部写入应拒绝，方案期间人工写入应拒绝。截图检查实际工作区，导出后另看 PNG。

涉及生成时保留真实 PNG、源/结果版本、操作编号、前后余额及失败步骤。结果未知先查原记录，不重复提交。只在明确范围内调用收费服务；纯样式修改无需生图。

日志和报告放在仓库外。开发实例的生成证据位于 `%APPDATA%/chiyo-manga-dev/executions/`，手动诊断客户端 `scripts/mcp-client.mjs` 的工具调用与图像证据位于 `%TEMP%/chiyo-v01-acceptance/`。客户端用于当前实例的逐步观察，不是自动外部 Agent 验收。

主进程改动前确认当前工程已保存、没有生成任务，并正常关闭 Chiyo；不要强杀用户实例或影响 NovelPrompt 的当前草稿。生产包只做构建检查，不用新 profile 宣称通过真实验收。
