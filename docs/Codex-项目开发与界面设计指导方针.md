# Codex 项目开发与界面设计指导方针

适用于 TypeScript、JavaScript、Vue、CSS/Less 项目的新功能、界面调整与模块重构，也覆盖测试和工程脚本。目标是代码易读、职责清晰，界面直接、统一、便于操作。

本文件完整规定代码写法、组件职责、样式组织、界面设计、文案和验收要求，可独立使用，无需另读代码规范或外部指南。新代码和重构模块遵守本文件；存量代码按模块逐步整理。

## 1. 使用方式与适用边界

- 可将本文件放入项目文档目录，并在项目根目录的 `AGENTS.md` 中明确要求：执行开发和界面任务前阅读本文件，按相关章节实现与验收。单独存放普通 Markdown 文件不代表 Codex 会自动读取。
- 临时任务可以直接附上本文件，并说明“按这份指导方针实施”。
- 已有项目先读取项目指令、构建脚本、格式配置、组件和设计变量；复用已存在的约定。发现本文件与实际配置冲突时，指出具体差异，不擅自全库改制。
- 用户对当前任务的明确要求优先；项目专有要求与通用默认不一致时，遵循当前项目约定并说明必要取舍。
- 不把全库格式化、语义重命名、结构重构、视觉修改和业务变更混成一个难以审阅的改动。
- 工具配置和样式迁移进度以实际文件与命令结果为准。不能把本文件列出的目标检查当作项目已经具备的能力。

## 2. 开始实现前

- 明确页面的使用者、主要任务、主要操作和实际内容，避免用宣传文案补足尚未明确的功能。
- 检查现有相似页面，复用导航、控件、图标、状态和视觉语言。
- 对新界面确定字体层级、间距尺度、颜色角色、圆角与布局密度；优先复用现有设计变量。
- 有参考图时，明确分别参考其布局、信息密度、排版或色彩，不机械照搬不适用的交互。
- 没有参考图时，工具类产品默认采用克制、紧凑但清晰的工作界面。普通实现选择自行推进，不因细小样式选择反复等待确认。

## 3. 代码格式与逻辑组织

- 使用 2 个空格缩进、UTF-8、LF 和文件末尾换行；格式化目标行宽为 100 字符，长 URL、协议内容和字符串不强行拆断。
- TS/JS 保持单引号、通常省略语句尾分号，由格式化工具处理必要的语法分隔。CSS/Less 声明必须有分号。
- 一行只放一条语句，每条变量声明独立书写，不用逗号声明多个不同职责的变量。
- `if`、`else`、循环及 `try/catch/finally` 使用花括号和多行代码块，简单提前返回也一样。
- 函数块体展开；只有单个纯表达式的短箭头函数可以保持一行。不用表达式隐藏副作用。
- 按输入校验、读取、计算、持久化和通知等实际步骤留空行，不机械地每行留空。
- 禁止嵌套三元表达式；简单二选一赋值可以使用三元，多条件业务使用命名变量、分支或函数。
- 多步数组处理链每步一行，复杂回调提取为具名函数。
- 禁止用 `condition && save()`、逗号表达式或多层链式赋值表达状态修改，使用显式分支。
- 多字段业务对象和复杂调用按字段、参数分行，简短坐标等按统一格式化结果处理。
- 不通过压缩、拼行或禁用格式化满足文件行数要求；按职责决定拆分。

不接受把多项业务操作压在一行：

```ts
const w = readPage(id), v = pageCurrent(w)
if (!v) return
const r = v.editor.regions.find(r => r.id === regionId); if (r) r.target = target
```

应使用明确命名、独立语句与显式分支：

```ts
const workspace = readPage(workspaceId)
const currentVersion = pageCurrent(workspace)

if (!currentVersion) {
  return
}

const targetRegion = currentVersion.editor.regions.find(
  (region) => region.id === regionId,
)

if (targetRegion) {
  targetRegion.target = target
}
```

可读性通过命名、分行和职责组织改善，不靠标点风格争论。

## 4. 命名与数据边界

- 变量和函数使用 `camelCase`；类型与 Vue 组件使用 `PascalCase`；CSS 类名使用有意义的 `kebab-case`，保留项目已有命名体系。
- 名称表达业务含义：使用 `workspace`、`version`、`region`、`proposal`、`message`、`fileStats`，包括回调参数。
- 避免 `w`、`v`、`r`、`cfg`、`tmp`、`obj`、`arr`、`fn` 等省略；含义不明确的 `data`、`result`、`item` 应具体化。
- 允许 `id`、`url`、`api`、`ipc`、`mcp`、`png` 等领域通用缩写，例如 `workspaceId`、`imageUrl`。
- 布尔值表达判断，例如 `isSaving`、`hasPendingChanges`、`canEditWorkspace`；操作使用具体动词，例如 `loadWorkspace`、`saveDraft`。
- 区分 `viewedVersion`、`adoptedVersion`、`sourceImage` 等不同角色，不笼统命名为 `current` 或 `selected`。
- 带单位的数据写明单位，例如 `timeoutMs`、`imageWidthPx`、`fileSizeBytes`。
- `x/y` 可用于局部坐标公式，常见数学符号可以用于短小且有公式解释的算法；循环优先用 `index`，`i/j` 仅限短小纯索引循环，不跨异步或嵌套业务流程。
- 错误参数用 `error`，事件参数用 `event` 或具体名称如 `pointerEvent`；泛型优先表达角色，如 `TRequest`、`TResult`，短小通用容器允许 `T`。
- 已持久化字段、IPC/MCP 参数、供应商协议字段不能随内部重命名改变。必要时在边界映射本地名称。
- 使用符号引用重命名并检查调用者，不进行全库单字母替换。

## 5. Vue 组件、模板与状态

- 标签有多个属性或指令时，每个属性独立一行，标签结束符由格式化工具统一。
- 模板只负责展示和事件绑定；保存、删除、生成等多步逻辑放入具名处理函数，不在 `@click` 中串联赋值和调用。
- 复杂展示条件放入有业务含义的计算属性，避免重复条件和多层三元。
- 按状态、派生状态、用户动作和生命周期组织代码，相关逻辑就近放置。
- 组件输入和事件明确，不向调用者暴露全部内部状态。
- 组件和 composable 按职责拆分，不把超大组件简单搬进一个超大 composable。
- 检查定时器、监听器、订阅等资源的释放，以及异步结果是否仍适用于当前页面或对象。
- 仅为实际复用需求抽象共享组件和逻辑，不为单个简单场景建立复杂通用框架。

模板写法示例：

```vue
<button
  class="workspace-save-button"
  :disabled="!canSaveDraft"
  @click="saveDraft"
>
  保存配置
</button>
```

## 6. CSS 与 Less

- 选择器、花括号和声明展开，每行一个属性；只有一个属性的规则也分行。
- 多选择器每个选择器一行；媒体查询、关键帧、伪类和伪元素保留清楚的独立结构。
- 新样式按布局、尺寸与间距、文字、颜色与边框、效果与动画分组。
- 整理存量样式时保留影响覆盖关系的声明顺序，尤其是简写与长写属性，不自动按字母排序。
- 主题和基础视觉值优先复用 CSS 自定义属性；功能样式留在对应组件或功能目录，公共样式只放真正复用的规则。
- 静态样式不堆入模板 `style`；与坐标和尺寸等状态绑定的动态样式可保留在绑定或 CSS 自定义属性中。
- 不通过层层嵌套、滥用 `!important` 或无边界全局选择器提高优先级；必要例外需说明原因。
- 不批量把 CSS 改成 Less。先选择独立组件试点、接入编译与检查，再按模块评估推广。
- Less 用于组件内聚样式、少量编译期变量和真实复用的 mixin；运行时主题值继续使用 CSS 自定义属性。
- Less 嵌套最多两层，即外层选择器加一层状态或子元素；不复刻 DOM 树，类名保持完整可搜索。
- 不引入全局隐式 mixin、复杂循环生成选择器或大范围 `extend`。
- 首次 Less 迁移保留选择器、优先级、加载顺序和 `scoped` 作用域，与视觉重做分开实施。
- 整理 CSS 格式不以引入 Less 为前提；首次迁移不同时改变样式的全局或局部归属。

CSS 写法示例：

```css
.workspace-toolbar {
  display: flex;
  align-items: center;
  gap: 8px;
  padding: 12px;
  border-top: 1px solid var(--line);
}

.workspace-toolbar__button:hover {
  background: var(--hover);
}
```

Less 写法示例：

```vue
<style scoped lang="less">
.workspace-toolbar__button {
  padding: 6px 10px;
  color: var(--text);

  &:hover {
    background: var(--hover);
  }

  &:disabled {
    opacity: 0.5;
  }
}
</style>
```

示例中的主题变量应由项目实际定义；已有同义变量时沿用原名称，避免引入重复变量。

## 7. 页面布局与设计感

- 工具类页面首屏直接呈现工作区、内容和主要操作，不默认添加欢迎横幅、宣传首屏或功能介绍。
- 通过对齐、比例、字体层级、间距、内容密度和交互反馈建立设计感，不靠增加文案和装饰填满页面。
- 禁止机械套用“英文小标签＋抒情大标题＋副标题＋卡片网格＋底部 Tip”的结构。
- 同类数据优先采用列表、表格、分组、分隔线和适当留白；不要给每个区块套独立圆角卡片，也不要卡片嵌套卡片。
- 卡片应有明确用途，例如独立重复内容或需要边界的交互单元；删除边框、阴影和背景仍不影响理解时，考虑取消容器装饰。
- 页面主标题、区块标题和控件标签保持明确层级；紧凑面板、侧栏和工具栏不使用宣传首屏级字号。
- 强调色用于主要操作、选中状态或关键反馈，状态色保持稳定含义；不为营造“高级感”默认叠加渐变、玻璃效果、发光背景和巨大阴影。
- 不为填补空白添加无依据的统计数字、装饰图标、徽章、英文标签或无关模块。
- 图标沿用项目现有图标库；不熟悉的纯图标控件应有可访问名称与适当的悬停、焦点说明。
- 动效用于反馈、状态变化和空间关系，不影响工作效率；支持减少动态效果的用户设置。
- 作品展示、品牌宣传或游戏可以采用更有表现力的布局，但仍遵守真实内容、清楚层级和直接文案的要求。

## 8. 界面文案与提示

- 标题直接命名对象或任务，例如“项目”“文件”“最近记录”“导出设置”。标题没有额外作用时可以删除。
- 不使用抒情、隐喻、口号和空泛价值表达，例如“开启创作之旅”“让灵感在此汇聚”“一切尽在掌握”。
- 按钮用明确动作，例如“新建项目”“上传文件”“保存”“导出 PDF”。
- 不默认给每个标题加副标题，不用同一句意思重复解释标题、按钮或导航。
- 不把设计理念、开发过程、技术实现、组件名称和功能宣传写进用户界面；面向开发者的工具只在相关任务确有需要时展示技术信息。
- 默认不添加常驻 Tip、温馨提示、小贴士、使用建议、教程式卡片。不得仅换一个名称继续保留。
- 帮助仅保留对当前操作必要的内容：格式与大小限制、错误恢复、不可逆后果和陌生概念；放在相关操作附近，并在适当时机显示。
- 不把必要字段标签、错误原因和关键限制全部藏进悬停提示；键盘和触屏用户也应能够获得相关信息。
- 空状态写清现状及下一步，例如“暂无项目”配“新建项目”；不添加鼓励式口号。
- 错误反馈说明发生了什么、可以如何恢复，不只写“出错了”，也不泄露无关内部信息。

| 避免 | 建议 |
| --- | --- |
| 让灵感在此汇聚 | 项目 |
| 开启你的高效创作之旅 | 新建项目 |
| 每一份努力，都值得被记录 | 最近记录 |
| Tip：点击右上角按钮添加项目 | 删除说明，保留清楚的“新建项目”按钮 |
| 温馨提示：本工具支持 PDF 格式 | 上传控件附近写“PDF，最大 20 MB”，限制须与实际实现一致 |

## 9. 修改顺序与检查

1. 读取现有规范、脚本和相关模块，确认本次范围与现有功能。
2. 界面改造先清理内容与信息层级，再调整布局，最后处理视觉细节；删掉冗余内容后重新安排空间。
3. 按职责实现，保留相关业务行为和外部数据契约；不顺手进行无关全库重构。
4. 运行项目实际存在、与改动相关的格式、静态检查、类型检查、测试和构建命令。
5. 界面变更启动并查看实际页面，使用可用浏览器工具或 Playwright 检查截图与交互，根据结果修正。
6. 交付说明实际改动、已执行的检查及仍未验证的内容，不把推测写成通过结果。

### 代码检查职责

| 检查方式 | 负责内容 |
| --- | --- |
| `.editorconfig` | 缩进、编码、换行和末尾换行；需要编辑器支持，不能单独视为强制检查 |
| Prettier | TS/JS/Vue/CSS/Less 机械格式、100 字符目标行宽和 Vue 多属性换行 |
| ESLint 与 TS/Vue 规则 | 分支花括号、一行语句数量、独立变量声明、嵌套三元、Promise 和类型边界；与格式配置协调后保持结构规则启用 |
| Stylelint | 样式有效性与约定，Less 使用对应语法支持，不自动重排声明 |
| 依赖边界检查 | 项目已配置的模块依赖方向与层级约束 |
| 人工或 Agent 审查 | 业务命名、逻辑分段、职责、生命周期与共享抽象是否合理 |

- 提供清楚区分的“只检查”和“自动修复”命令；检查覆盖 `src`、`scripts`、`tests`，样式检查覆盖全部 renderer CSS/Less/Vue。目录名称不同的项目覆盖对应职责目录，不能仅检查正在修改的少量文件而宣称已完成全量检查。
- 不因存量问题全局关闭规则，不宣称尚未配置的检查已经生效。
- 每批改动都要审查业务命名、逻辑分段、模块职责和共享抽象；不能用格式化通过代替可读性审查，也不能仅凭变量长度判断命名质量。
- 格式化、语义重命名、职责拆分分别形成可审阅的改动批次，不自动代用户提交版本。
- 重命名后检查类型、导出、模板引用、跨进程契约和受影响测试；样式调整后检查视觉和交互。
- 对业务行为变化补充有意义的测试；不为纯排版变化增加只验证代码长相的业务测试。

### 界面验收

- 首屏能直接找到主要内容和主要操作。
- 标题直白，副标题有必要，没有抒情口号和无关英文标签。
- 没有常驻泛泛提示、重复解释和无意义装饰容器。
- 字号、间距、颜色、图标和控件行为在相关页面保持一致。
- 桌面与移动端布局，或桌面专用工具的最小支持窗口尺寸，均无异常溢出、遮挡和文字截断。
- 检查长标题、长文件名、大量内容、空状态、加载、成功、错误与禁用状态。
- 检查默认、悬停、键盘焦点、选中状态及相关弹窗；不能只验收静态截图。
- 图标控件有可访问名称，键盘操作路径和焦点可见，状态不只依赖颜色表达。
- 动态内容、按钮加载状态和缩放不会导致无必要的布局跳动。
- Less 迁移还需检查开发启动、生产构建、作用域、样式覆盖和窗口缩放回归。
- 无法运行页面、执行检查或查看截图时，明确标记未验证，不声称已通过。

## 10. 可直接使用的任务指令

> 请先读取本指导方针和项目已有约定，再实施本次需求。代码保持业务命名、显式逻辑、清楚职责与现有格式。界面直接展示内容和操作，删除抒情标题、重复副标题、常驻 Tip 与无意义装饰卡片；必要的字段标签、操作限制、错误恢复信息必须保留。复用现有设计变量与组件，避免无关重构。完成后执行相关检查，并查看实际页面的截图与交互；说明实际验证结果。
